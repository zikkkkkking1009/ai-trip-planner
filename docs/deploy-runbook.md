## 阶段三：花生壳免费档（这一步必须你本人在场）

> **产品入口怎么选**：在花生壳官网那页选「**搭建网站**」——我们就是把本地网站发布出去。
> - ❌ **花生壳 Drop**：纯静态托管，官方明确排除 WebSocket / 动态 API（详见 3.4）
> - ❌ **花生壳盒子 / 盒子X**：硬件，要买，软件客户端就够
> - ⚠️ **场景映射**：一键开通的增强服务（带宽 10 Mbps），属**付费**档，别点开通
> - ⚠️ **花生壳 CLI**：也能做内网穿透（还能被 AI 直接调用，很省事），但**匿名隧道只有 24 小时有效期** ——
>   我们要的是"朋友长期能用"，所以走**客户端 + 内网穿透映射**（绑定账号，长期有效）
> - ✅ **搭建网站** → 下载 Windows 客户端 → 内网穿透 → 添加映射

### 3.0 免费档的真实配额（2026-09-28 从官网核过，以控制台实际显示为准）

| 项 | 免费档 |
|---|---|
| 映射条数 | **1 条**（部分页面写 2~3 条，以控制台为准） |
| 带宽 | **1 Mbps** |
| 流量 | **每月 1 GB** |
| 外网端口 | 动态（删除映射后不恢复）；**HTTPS 映射固定 443** |
| 壳域名 | 赠送，**有效期 1 年** |
| 访问控制（密码 / IP 白名单） | ❌ **付费功能** |

**1 GB 够不够？** 够。算一下：页面本体约 250 KB，一次规划的 JSON 几十 KB；
**地图瓦片和景点图片都是浏览器直连高德 CDN，不走隧道**。按每次完整使用约 500 KB 估，
1 GB ≈ **2000 次**。朋友圈规模（≤10 人）绰绰有余。1 Mbps 下页面约 2 秒打开，能接受但不快。

⚠️ **免费档没有"访问密码"（那是付费功能）** —— 这恰好说明我们自己做的 `APP_TOKEN` 不是过度设计，
而是**免费档下唯一的门**。别跳过阶段一的令牌配置。

⚠️ 同一账号**不能多设备同时登录**（会互踢，映射随之失效）—— 别在另一台机器上同时登这个账号。

### 3.1 账号与隧道

1. 注册贝锐账号 → **实名认证**（绕不过）
2. **产品入口选「搭建网站」**（截图里那页）—— 我们就是把本地网站发布出去，它走的就是免费内网穿透映射。
   ❌ 不要选「花生壳 Drop」（纯静态托管，跑不了 FastAPI 后端）；
   ❌ 不要买「花生壳盒子 / 盒子X」（硬件，没必要，软件客户端就够）；
   ⚠️「场景映射」是**一键开的增强服务（带宽 10 Mbps）**，属于付费档，别点进去开通。
3. 下载并安装**花生壳客户端（Windows）**，登录 → 内网穿透 → 添加映射：
   - 应用类型 / 映射类型：**HTTPS**（不是 HTTP）—— 免费档 HTTPS 映射外网端口固定 443
     且花生壳自动部署 SSL 证书，浏览器直接 `https://域名` 访问，前端也会自动切到 `wss`
   - 内网主机：`127.0.0.1`
   - 内网端口：`8000`
   - 外网域名：选赠送的壳域名
4. 客户端保持开机自启 + 常驻（**客户端不在线 = 服务下线**）

### 3.2 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<你的域名>/health      # 期望 200（无需令牌）
curl -s -o /dev/null -w "%{http_code}\n" https://<你的域名>/favorites   # 期望 401（已上锁）
```

浏览器打开 `https://<域名>/app` → 右上角填令牌 → 走一遍规划。
HTTPS 由花生壳提供，前端的 `wss` 判断代码已就位（会按 `location.protocol` 自动切）。

> ⚠️ **必须实测 WebSocket**（这是唯一没法离线验证的一环）：
> 规划进度条走 `/ws/{task_id}`，而花生壳的 HTTPS 映射是 HTTP 层代理，
> **能否透传 WebSocket 的 Upgrade 取决于它**。用 DevTools → Network → WS 看：
> - **通了**：进度条正常推进，收工。
> - **不通**：进度条会一直停在 0%（任务其实在后端照跑，只是前端收不到推送）。
>   应急方案：把映射类型改成 **TCP**，此时外网地址是 `域名:动态端口`、**没有 HTTPS**
>   （页面走 `http://`，`ws://` 就能用）。代价是回到明文，且端口删了不恢复。
>   若真要用 TCP，阶段一里把 `APP_TOKEN` 配好就更重要了（明文传输下它是唯一的门）。

### 3.4（可选）静态宣传页 —— Drop 唯一用得上的地方

**先说结论：Drop 跑不了本应用**，官方页面自己写明了 ——
"如果应用涉及 **WebSocket**、动态 API、SSR 等需要动态计算的服务，则不属于静态托管的适用范围，
应考虑使用内网穿透映射能力"。我们三样全占（`/ws/{task_id}` 进度推送、`/plan/async` 后端求解、Python 求解器）。

**更根本的原因不是"跑不了 Python"，而是 Key 不能在浏览器里**：做成静态页，前端就得自己持有
LLM 与高德 Key，任何人 F12 打开就能偷走烧光。所以这不是选型问题，是硬边界。

但 Drop 拿来放**宣传页**很合适，而且比挂在隧道里更好：

| 优势 | 说明 |
|---|---|
| 不用电脑开机 | 文件托管在云端，与本地设备解耦（隧道版必须本机常开） |
| 微信里点开不弹警告 | 花生壳的域名是**已备案**的，聊天窗口/朋友圈直接点开 |
| 链接长期有效 | 免注册可先试，登录账号**认领**后长期保留 |
| 可拖单个 HTML | 无需打包成 zip/文件夹 |

做法：把真应用的地址 + 一句介绍 + 二维码放进一个 `index.html`，拖到 Drop 即可。
**别期待它承载任何功能**（页面上只有静态文字，所有交互仍在真应用里）。

## ⚠️ 与原计划的差异（三处修正）

1. **绑定 `127.0.0.1` 而不是 `0.0.0.0`**。花生壳客户端跑在**同一台机器**上，连的就是本机
   `127.0.0.1:8000` —— 绑 `0.0.0.0` 对它没有任何额外好处，却把服务暴露给整个局域网
   （同一 WiFi 下任何人都能直连，还能绕过隧道伪造 `X-Forwarded-For`）。少一个暴露面。

2. **限流的 IP 取值要认 `X-Forwarded-For`**。这是原计划没提到的坑：隧道场景下所有请求都来自
   本机，`request.client.host` **恒为 127.0.0.1** —— 直接按它限流会把所有朋友算成**同一个人**，
   30 次/分钟 被全场共享（人一多就集体 429）。代码里已改为：直连方是回环时才采信 XFF，
   否则用真实 peer；而且**取 XFF 的最后一个值而不是第一个** —— 标准反代是**追加**式写入
   （`客户端自带的` + `, ` + `真实 peer`），第一个恰好是攻击者能伪造的那段，取它等于
   一个伪造头换一个限流桶、把限流做废。

   **上线后建议实测一次**（推断不能替代事实 —— 花生壳到底怎么写的这个头，只有试了才知道）：

   ```bash
   # 从隧道外面（比如用手机热点）发一个伪造 XFF 的请求，然后看服务日志里的限流/请求记录
   curl -H "X-Forwarded-For: 1.2.3.4" https://<你的域名>/health
   # 再在服务端日志里确认解析出的 IP：如果恒为 127.0.0.1 或恒定同一个值，
   # 说明花生壳没透传真实 IP —— 那么"每 IP 限流"实际是"全场共享一份额度"，
   # 对策：把 RATE_LIMIT_PER_MIN 调大到朋友规模不再误伤（如 200），或改用令牌级计数。
   ```

3. **`/docs` 与 `/openapi.json` 保持公开 —— 刻意为之，不是漏网**。首页 footer 有意链到
   Swagger UI（作品集要展示），文档只暴露接口形状、不含任何 Key，而文档里"Try it out"能点的
   花钱接口背后照样要令牌。若以后要收，做法是「`docs_url=None` + 自建受令牌保护的 `/docs`」，
   而不是直接关掉（那会把首页那个链接变成死链）。
   ⚠️ 顺带一提：Swagger UI 的 JS/CSS 是 FastAPI 默认从 CDN 拉的，与本站「零 CDN」的纪律不一致 ——
   属于既有情况，本次未动。
