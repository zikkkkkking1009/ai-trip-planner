攻略收藏了一堆，
行程还是排不明白。

不是你不会做攻略，是「排行程」这件事本身就是道约束题。

信息是散的

景点、门票、开门时间、交通方式散在十几篇笔记和视频里， 拼成一条顺路的线，比看完它们还费劲。

时间是算不清的

几点出门、先去哪、每处待多久、几点前回到酒店， 人工排一天就要一小时，还容易把行程排进关门时间。

结果是不敢保证的

排完不知道会不会超预算、绕多大弯路； 「应该没问题」和「保证没问题」是两回事。

路书的答案是一个分工

LLM 只负责读懂攻略；时间窗、预算、动线这些硬约束，交给确定性求解器， 最后由独立校验器复核。让 AI 干它擅长的，不许它碰它保证不了的。

输入

一段攻略

游记、攻略帖，或者随手列的想去的清单。也可以不粘， 直接从 25 城预置景点里挑。

处理

四道工序

LLM 抽取景点与偏好 → 对齐高德真实坐标 → 求解器在预算与时间窗里排期 → 独立校验器复核。

产出

一份能执行的行程

逐日时间线、地图路线、通勤与预算账、 按时走完的概率，以及可分享的长图。

亮点

六个能感知的好处，每个都有工程托底

先把能做到什么说清楚；实现原理放在括号里，给想较真的人。

说句话就能改行程

「明天下午加个咖啡馆」「酒店换到西安站附近」，改完自动重排并复校验， 支持多轮对话。（LLM 解析意图，确定性代码执行，不走「重新生成一遍」）

不排进关门时间，不超预算

开放时间、通勤、每晚回酒店、门票预算，全部是硬约束。 50 组对照实验：0 时间冲突、0 预算违规 （带时间窗定向问题，多起点随机重启 + 2-opt）。

住宿是锚点，不是景点

每天从酒店出发、按时回酒店，往返通勤计入时间窗与统计， 而不是被当成某个景点随手插进哪一天。

告诉你按时走完的概率

1000 次蒙特卡洛模拟给出按时概率与风险点排名； 开稳妥模式，用 1 个景点换 92 个百分点的确定性。

别名不迷路

「兵马俑」「紫禁城」对齐到高德真实坐标，认不准的转人工点选， 绝不静默猜一个。（Top-5 召回 + 四路打分 + 低置信度 LLM 仲裁，F1 100%）

数字都有出处

实验固定随机种子，脚本与结果文件在仓库里可复现； 求解结果由独立校验器复核，历史上真抓到过优化步骤破坏约束。

已知局限

写清楚哪里还不行

行程规划是要拿去执行的，所以宁可先说清楚边界，也不假装全知。

门票与停留时长是近似值。 坐标来自高德真实抓取，票价与停留是演示参数；高德搜索接口实测不返回票价（8 个知名收费景点覆盖率 0%），所以不编数字。
稳健性模拟的噪声参数未经真实日志标定。 绝对概率不应当作精确值，风险点的相对排序才是可用的部分。
无数据库与用户体系。 历史与收藏保存在本地文件，暂不支持多用户隔离。
没有配置 LLM Key 时，抽取 / 评价 / 总评 / 对话改行程四条链路不可用。 这不是崩溃，是明确降级：/extract、/plan/review、/plan/edit 返回 503 并说明原因，AI 评价区整块隐藏 —— 不做假数据填充。手工填景点、排期、地图、天气、稳健性模拟都不依赖 LLM，零 Key 仍可完整走通。
无网络 Key 时通勤降级为直线估算。 配置高德 Key 后才会使用真实驾车时长；已缓存的通勤时长在无 Key 时仍会被复用，所以「无 Key」不等于「一定在估算」。

不需要准备什么

能跑是底线，跑不了的会明说；这一页写的是「打开就有」的部分。

不需要注册登录。 打开即用；行程、收藏保存在你自己的设备上。
不需要任何 Key 也能玩。 内置 25 城演示数据，选点、排期、地图、天气、稳健性模拟零 Key 完整可用； 抽取、对话改行程、AI 总评依赖 LLM Key，未配置时明确提示而不是装死。
不需要付费 API。 高德开放平台免费档即可；未配置时通勤降级为直线估算并如实标注， 不会拿估算冒充真实驾车时长。

现在跑着的这一套，是什么状态

同一个 /health 在给机器读之外，也该让人一眼看懂：哪些能力现在是真的可用，哪些是降级。

数据来自 GET /meta（与 /health 同源，不是另算一份）。打开页面时实时读取，刷新即最新。 密钥只显示「已启用 / 未启用 / 已配置但无效 / 未探测到」四种状态与原因，不回传任何值； 可用性是服务启动时真实探测出来的（结果缓存 6 小时），不是看一眼配置文件就下结论。
